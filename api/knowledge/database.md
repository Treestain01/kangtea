# Database

## What is stored

Postgres on Vercel through the Neon Marketplace integration holds the catalogue: the store, menu categories, menu items, sugar and ice levels, and toppings.
Orders and accounts are still local to the browser (see `webapp/knowledge/orders.md`).

## Source of truth

`seed.json` at the repository root is the base template for the database.
Its shape is `{ store: Store, menu: Menu }` from `@bbt/shared`, checked by `SeedSchema` in `src/catalogue/seed.ts`.
Change the menu by editing `seed.json`, then run the root `db-seed` skill against each environment.
`test/seed.test.ts` fails if the file stops matching the contract.

## The catalogue abstraction

Routes read through the `Catalogue` interface (`src/catalogue/types.ts`): `getStore()` and `getMenu()`.

| Implementation            | File                        | When                                                             |
| ------------------------- | --------------------------- | ---------------------------------------------------------------- |
| `createPostgresCatalogue` | `src/catalogue/postgres.ts` | `DATABASE_URL` is set. Production and preview on Vercel.         |
| `createSeedCatalogue`     | `src/catalogue/seed.ts`     | `DATABASE_URL` is unset. Local dev without a database and tests. |

`createCatalogue(env)` in `src/catalogue/index.ts` picks one and logs a warning when it falls back to the seed.
The entrypoints (`src/server.ts` locally, `index.ts` on Vercel) pass the result into `createApp(env, { catalogue })`.
Tests pass the seed catalogue or a fake.

## Schema and migrations

| Piece              | File                             | Notes                                                                                  |
| ------------------ | -------------------------------- | -------------------------------------------------------------------------------------- |
| Drizzle schema     | `src/db/schema.ts`               | Tables `stores`, `menu_categories`, `menu_items`, `option_levels`, `toppings`.         |
| Connection         | `src/db/client.ts`               | `connect(url)` opens a small `pg` pool. `Db` is the driver neutral type.               |
| Migrations         | `drizzle/*.sql`, `drizzle/meta/` | Generated by `pnpm db:generate`, committed, applied by `pnpm db:migrate` or `db:seed`. |
| Seed logic         | `src/db/seed.ts`                 | Deletes every catalogue row and inserts the seed in one transaction.                   |
| Wipe logic         | `src/db/wipe.ts`                 | Drops schema `public` (recreated empty) and schema `drizzle`.                          |
| drizzle-kit config | `drizzle.config.ts`              | Schema path and output folder only. Generating needs no connection.                    |

Sugar and ice levels share `option_levels`, told apart by the `option_group` enum.
`sort_order` columns keep the display order the seed lists things in, so a menu reads back in the same order it was written.
`hours` is `jsonb` and `address_lines` and `tags` are `text[]`; the shared schema validates them on the way out.

## Changing the schema

1. Edit `src/db/schema.ts`.
2. Run `pnpm --filter @bbt/api db:generate --name <what-changed>` and commit the new file under `drizzle/` with its `meta` snapshot.
3. Update `src/db/seed.ts`, `src/catalogue/postgres.ts` and, if the contract changed, `packages/shared` first.
4. `test/db.test.ts` runs the migrations against PGlite, so a broken migration fails `pnpm test`.
5. Apply with the `db-seed` skill (it migrates first) or `pnpm db:migrate` when the data should be kept.

## Scripts

All run from `api/` with `DATABASE_URL` in `api/.env` or the environment, and print the target host before acting.

| Script             | Does                                                                     | Needs `--yes` |
| ------------------ | ------------------------------------------------------------------------ | ------------- |
| `pnpm db:generate` | writes a migration from the schema diff                                  | no            |
| `pnpm db:migrate`  | applies pending migrations, keeps data                                   | no            |
| `pnpm db:seed`     | applies pending migrations, then replaces the catalogue with `seed.json` | yes           |
| `pnpm db:wipe`     | drops everything, including the migration journal                        | yes           |

The root skills `db-seed` and `db-wipe` wrap these with the Vercel environment steps.

## Testing

`test/db.test.ts` uses PGlite (Postgres compiled to WebAssembly) in process: migrate, seed, read back through the Postgres catalogue, seed again, wipe, migrate again.
No test opens a network connection, so `pnpm test` needs no database.
The `Db` type is the common supertype of the `pg` and PGlite Drizzle databases, which is what lets the same code run in both.

## Environment

`DATABASE_URL` is the pooled connection string the Vercel Neon integration provides.
Locally, `src/server.ts` and the scripts call `loadDotEnv()`, which reads `api/.env` when present.
An empty value counts as unset.
